# Prompt: API contract interview evaluation

Evaluate a backend candidate's answer to an API design exercise. Separate observations into contract clarity, data ownership, persistence correctness, authorization, failure handling, observability, and rollout safety. For each category, quote or summarize the candidate's evidence, identify the missing consideration, and assign a calibrated signal for the target seniority. Do not reward framework name-dropping without reasoning. End with three follow-up questions that test the most consequential uncertainty.

Use HTTP, OpenAPI, PostgreSQL, and OWASP terminology only when it clarifies the hiring signal. Do not infer production experience from a technology keyword alone.

References: [OpenAPI](https://spec.openapis.org/oas/latest.html), [MDN HTTP](https://developer.mozilla.org/en-US/docs/Web/HTTP), [PostgreSQL constraints](https://www.postgresql.org/docs/current/ddl-constraints.html), [OWASP API Security](https://owasp.org/API-Security/).
