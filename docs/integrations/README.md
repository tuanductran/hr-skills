# Ecosystem Integrations

> How HR Skills extends interoperability across AI agent platforms and marketplaces.

## What it is

HR Skills is authored once, against the open **Agent Skills** specification
(`SKILL.md` frontmatter + Markdown), and distributed to multiple consumption
surfaces without forking content per platform.

This document is authoritative for which platforms are supported today, which
are candidates, how installation works, and how compatibility is verified.

## Design principle: one format, many consumers

No skill content is duplicated or platform-forked. Every integration is one of:

1. **A copy/reference mechanism** — pointing a platform at `skills/hr-*/` or
   `.claude-plugin/marketplace.json` as-is.
2. **A generated adapter/manifest** — a build step that derives a platform-native
   manifest from canonical skill metadata.

If a platform requires hand-written forks of skill content, it is not a
supported integration target.

## Supported platforms

| Platform | Mechanism | Status | Notes |
| --- | --- | --- | --- |
| Claude Code | Copy `skills/hr-*` into `~/.claude/skills/` | 🟢 Supported | Recommended path; auto-discovery, no manifest needed |
| Claude.ai (Projects) | Upload `SKILL.md` to Project Knowledge | 🟢 Supported | Single-skill or multi-skill upload |
| Claude Code Marketplace | `.claude-plugin/marketplace.json` | 🟢 Supported | Generated by `bun run sync` |
| Direct clone / vendoring | `git clone` + copy `skills/` | 🟢 Supported | No tooling dependency; works with Agent Skills-compatible runtimes |
| Codex plugin manifest | `.codex-plugin/plugin.json` | 🟡 Manifest generated | Generated by `bun run sync`; runtime compatibility is not claimed by this repository solely because the manifest exists |
| Codex plugin marketplace manifest | `.agents/plugins/marketplace.json` | 🟡 Manifest generated | Generated and schema-validated by `bun run sync`; marketplace availability remains platform-dependent |
| Generic Agent Skills runtimes | Read `SKILL.md` frontmatter directly | 🟡 Candidate | Compatible when the runtime implements the open spec correctly |
| OpenAI-style custom agents / GPTs | Adapter: registry → tool/instruction bundle | 🟡 Candidate | No dedicated generated adapter is committed |
| LangChain / CrewAI / other orchestration frameworks | Adapter: registry → tool schema | 🟡 Candidate | `registry/skills.json` contains structured fields an adapter would need |

🟢 Supported means the documented consumption path is implemented and verified
by this repository. 🟡 Manifest generated means HR Skills produces the native
artifact, but does not claim that every target runtime or marketplace has been
validated end-to-end.

## Installation & onboarding

### Claude Code

```bash
cp -r skills/hr-recruiting ~/.claude/skills/
cp -r skills/hr-* ~/.claude/skills/
```

### Claude.ai

1. Create or open a Project.
2. Upload the desired `SKILL.md` and, where useful, its `content/`, `prompts/`, and `examples/` files.
3. Start chatting.

### Direct clone

```bash
git clone https://github.com/tuanductran/hr-skills.git
```

Point the runtime's skill loader at `skills/hr-*/SKILL.md`.

## Generated integration artifacts

`bun run sync` keeps these committed manifests aligned with canonical skill and
package metadata:

- `.claude-plugin/marketplace.json`
- `.claude-plugin/plugin.json`
- `.codex-plugin/plugin.json`
- `.agents/plugins/marketplace.json`
- root `SKILL.md` routing table

These are generated artifacts, not independent sources of truth.

## Adding a new platform integration

1. Confirm the platform can read `SKILL.md` directly or consume a generated manifest.
2. Prefer a generator under `packages/hr-skills-build/src/server/build/` over hand-written platform content.
3. Wire the generator into the existing `sync`/validation pipeline.
4. Document the platform and its limitations here.
5. Add an integration test before claiming full support.

## Integration testing strategy

Compatibility is checked at three layers:

1. **Format-level:** `bun run validate` checks skill frontmatter and structure.
2. **Manifest-level:** generated artifacts are regenerated or validated against canonical metadata.
3. **Platform-level:** a smoke test confirms that the documented platform can load at least one skill without altering its content.

A generated manifest alone is not sufficient evidence of end-to-end platform support.

## Backward compatibility

Existing integrations remain based on the canonical `SKILL.md` files and
registry. New adapters should be additive and must not require platform-specific
forks of skill content.

## Platform limitations

- **claude.ai Project Knowledge** has per-project upload limits; large libraries may need to be split across Projects.
- **Codex manifests** are generated and schema-validated here, but this repository does not claim marketplace/runtime support merely from manifest generation.
- **Generic Agent Skills runtimes** vary in strictness; HR Skills targets the published spec rather than runtime-specific frontmatter.

## Platform-specific implementations

HR Skills deliberately avoids integrations that require:

- forking or rewriting `SKILL.md` content per platform
- platform-only frontmatter fields consumed by a single runtime
- maintaining a second, hand-edited copy of generated manifests
